ConsentBank

API de partage de données bancaires avec consentement du client, dans l'esprit du cadre fédéral des services bancaires axés sur les consommateurs : le client choisit quoi partager, avec qui et pour combien de temps, et peut tout retirer en un clic. ASP.NET Core 10, OpenIddict, portail Blazor. Données fictives.

Le parcours

  1. Requête poussée (PAR). L'application « Budget Futé » envoie sa demande au serveur, côté serveur, avec son secret et le défi PKCE (S256). Elle reçoit un request_uri à usage limité.
  2. Autorisation. Le navigateur du client arrive sur /connect/authorize avec ce seul request_uri : aucun paramètre sensible dans l'adresse.
  3. Connexion du client à sa banque (cookie sécurisé, formulaire protégé contre le CSRF).
  4. Consentement explicite. Le client voit l'application, ce qu'elle pourra lire, choisit les comptes partagés et la durée (30, 90 ou 365 jours), puis autorise ou refuse.
  5. Code puis jeton. Le code (valide 1 minute, usage unique) est échangé contre un jeton d'accès de 10 minutes, seulement avec le bon vérificateur PKCE.
  6. Appel à l'API. Chaque appel vérifie le jeton, la portée, l'autorisation OpenIddict et le consentement en base : seuls les comptes choisis sont visibles.
  7. Révocation. Depuis le portail Blazor, le client retire l'accès : l'autorisation et ses jetons sont révoqués, l'appel suivant est refusé.
  8. Journal d'audit chaîné. Chaque événement (consentement, jeton, consultation, révocation) est enregistré avec l'empreinte SHA-256 de l'entrée précédente : toute altération est détectée.
